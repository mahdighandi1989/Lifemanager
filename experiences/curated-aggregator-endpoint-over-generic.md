# Curated aggregator endpoint over generic

## 🎯 چالش / Challenge

یک اپلیکیشنِ چنددامنه‌ای که «جزیره‌ای» شده. یک لایهٔ گردآورندهٔ خوب هم دارد —
چند منبعِ ثبت‌شده که هرکدام از یک دامنه چیزی دربارهٔ کاربر استخراج می‌کنند و
یک ساختارِ واحد برمی‌گردانند. ولی این لایه **یک مصرف‌کننده** دارد و اجزای
نمایشش داخلِ همان یک صفحه گیر افتاده‌اند.

راه‌حلِ بدیهی: یک endpointِ عمومی بساز که همه‌چیز را بدهد، یک کامپوننتِ مشترک
دربیاور، و روی صفحهٔ اصلی بگذار. **این کار درست است ولی ترتیبش خطرناک است.**

## 💡 راه‌حل / Solution

**قبل از انتشار، گردآورنده را روی یک پایگاه‌دادهٔ کم‌داده اجرا کن و خروجی را
بخوان.** نه تست بنویس — اجرا کن و جمله‌ها را با چشمِ خودت ببین.

در موردِ ما، با ۸ ردیف در دیتابیس، خروجیِ خام **دقیقاً یک جمله** بود: یک
نمرهٔ منفی دربارهٔ شخصیتِ کاربر. یعنی تنها چیزی که سیستم دربارهٔ صاحبش
می‌گفت یک قضاوتِ منفی بود — و کلِ ۱۷۰۰ تست سبز بود.

چرا این اتفاق ساختاری است و تصادفی نیست:

- منابعی که **بینشِ خوب** می‌دهند معمولاً به دادهٔ زیاد یا سرویسِ بیرونی
  نیاز دارند (مدلِ زبانی، هفته‌ها لاگ، تاریخچهٔ تراکنش) و روی دیتابیسِ کم‌داده
  **ساکت** می‌مانند — که رفتارِ درستی است.
- منابعی که از **نسبت و شمارش** ساخته می‌شوند با دو ردیف هم شلیک می‌کنند.
- پس روی داده‌ی کم، **دقیقاً بدترین زیرمجموعه** باقی می‌ماند.

راه‌حل: **گزینش، خودِ قابلیت است.** endpoint با یک پیش‌فرضِ تنگ منتشر می‌شود:

```python
QUIET_GROUPS = ("unlinked", "facts")        # خراب نیستند، جای دیگری دارند
QUARANTINED_KEYS = ("diligence", "interests")  # اثباتاً معیوب‌اند

def curate(items, *, groups=None, include=None, surface=""):
    out = ([i for i in items if i["group"] in set(groups)] if groups
           else [i for i in items if i["group"] not in QUIET_GROUPS])
    out = [i for i in out if i["key"] not in QUARANTINED_KEYS or i["key"] in (include or [])]
    if surface:                                  # opt-in صریح، نه عددِ salience
        out = [i for i in out if surface in (i.get("surfaces") or [])]
    return out
```

و **هیچ‌چیز حذف نمی‌شود**: مصرف‌کنندهٔ قدیمی همچنان همه‌چیز را می‌گیرد،
و هر کنارگذاشته‌شده با یک پارامتر برمی‌گردد. علتِ هر کنارگذاشتن، با شواهدِ
اجراشده، جایی مکتوب می‌شود.

## 🧪 نمونه کد (Anonymized)

پروبی که تصمیم را عوض کرد — پنج دقیقه کار، و ارزشش از کلِ تحلیلِ ایستا بیشتر بود:

```python
async def probe():
    engine = create_async_engine("sqlite+aiosqlite:///:memory:")
    async with engine.begin() as c:
        await c.run_sync(Base.metadata.create_all)
    async with Session() as db:
        seed_a_realistic_but_thin_dataset(db)       # ~8 rows, not 8000
    async with Session() as db:
        out = await aggregator.collect(db, user_id)
        for item in out["items"]:                   # READ THEM. OUT LOUD.
            print(f"[{item['tone']}] {item['statement']}")
```

و برای «چه چیزی اجازه دارد روی کدام صفحه بیاید»، یک فهرستِ صریح روی خودِ
آیتم — نه یک عدد:

```python
@dataclass
class Item:
    ...
    surfaces: List[str] = field(default_factory=list)   # خالی = فقط صفحهٔ گردآورنده
```

## ⚠️ نکات حیاتی / Pitfalls

- **تستِ سبز چیزی دربارهٔ ارزش نمی‌گوید.** همهٔ قیدهای ساختاری (هر آیتم باید
  شواهد داشته باشد، باید لحن داشته باشد، باید لینکِ منبع داشته باشد) را یک
  آیتمِ کاملاً بی‌ارزش هم برآورده می‌کند. ساختار قابلِ اجباری‌کردن است؛ معنا نه.
- **دیتابیسِ توسعه‌دهنده پر است، دیتابیسِ کاربرِ تازه خالی.** اگر فقط روی
  دادهٔ کامل تست کنی، بدترین حالت را هرگز نمی‌بینی.
- **«این دوره» را بدونِ پنجرهٔ زمانی ننویس.** یک نسبتِ مادام‌العمر که خودش را
  «اخیراً» جا می‌زند، اتهامی است که کاربر هیچ راهی برای بهترکردنش ندارد.
- **دسته‌بندِ زیررشته‌ای برای زبان‌های غیرِانگلیسی فاجعه است.** `kw in text`
  با کلیدواژهٔ کوتاه، تقریباً هر متنی را به یک دسته می‌اندازد. حتماً روی
  کلمه‌های واقعیِ زبانِ هدف اجرا و چاپش کن.
- **عددِ salience نساز.** آستانه را آن‌قدر تنظیم می‌کنند تا بی‌معنا شود. یک
  فهرستِ صریح از سطح‌ها، در diff خوانا است و کسی باید پایش بایستد.
- **آیتمِ گردآورنده باید به «همان ردیف» لینک بدهد، نه به صفحه.** وگرنه پُلی
  ساخته‌ای که کاربر را دمِ در رها می‌کند (نگاه کن به
  `addressable-rows-not-just-pages`).

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

۱. قبل از عمومی‌کردنِ هر لایهٔ گردآورنده، آن را روی **کم‌ترین دادهٔ باورپذیر**
   اجرا کن و خروجی را بخوان. اگر خجالت‌آور است، همان‌جا متوقف شو.
۲. آیتم‌ها را به سه سطل تقسیم کن: **معیوب** (اثبات کن، بعد قرنطینه)،
   **درست ولی نامناسبِ این سطح** (پیش‌فرض ساکت، با درِ بازگشت)، و **خوب**.
۳. پیش‌فرض را تنگ بگذار و بازگشت را ارزان: `?groups=`, `?include=`.
   این هم قاعدهٔ «هیچ قابلیتی حذف نمی‌شود» را نگه می‌دارد هم سطحِ تازه را تمیز.
۴. اولین مصرف‌کننده را همان صفحهٔ موجود بگذار (صفر مواجههٔ تازه)، نه صفحهٔ
   اصلی. صفحهٔ اصلی کامیتِ بعدی است.
۵. «کدام آیتم روی کدام سطح» را یک فهرستِ صریحِ opt-in کن، نه یک آستانهٔ عددی.
۶. علتِ هر کنارگذاشتن را با **شواهدِ اجراشده** بنویس، نه با نظر. «اجرا کردم،
   این را چاپ کرد» یک استدلال است؛ «به‌نظرم مفید نیست» نیست.
