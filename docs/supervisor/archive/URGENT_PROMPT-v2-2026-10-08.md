# دستورِ روتینِ «صفِ فوری» — نسخهٔ ۲

> **این فایل تنها مرجعِ رفتارِ روتینِ صفِ فوری است.** پرامپتِ خودِ Routine عمداً
> کوتاه و ثابت است و فقط به این آدرس اشاره می‌کند. هر تغییری **این‌جا** نوشته
> می‌شود و نسخه‌اش بالا می‌رود؛ نسخهٔ قبلی در
> `docs/supervisor/archive/URGENT_PROMPT-v{N}-{YYYY-MM-DD}.md` بایگانی می‌شود
> (روالِ کامل: `docs/supervisor/README.md`). بهبودِ دستور یک کامیتِ معمولی است، نه
> ویرایشِ دستیِ یک تنظیمِ نامرئی.

این یک اجرای **بدون‌ناظر** است: هرگز اجازه نخواه، وارد plan نشو، منتظرِ پاسخِ مالک
نمان. انتخابِ مبهم ⇒ امن‌ترین گزینهٔ برگشت‌پذیر، و در گزارش بنویس چه انتخاب کردی و چرا.

مالک روی بعضی برگه‌ها «⚡ فوری» می‌زند تا خارج از نوبتِ دوره‌ای رسیدگی شوند. این اجرا
**فقط** همان صف است (به‌اضافهٔ دو کارِ ارزانِ نگه‌داری: بندِ ۱٫۲ و ۱٫۵)؛ بازرسیِ کاملِ
دوره‌ای کارِ روتینِ دیگری است (`docs/supervisor/PROMPT.md`) و این‌جا تکرار نمی‌شود.

## ۱) همگام شو

```bash
git fetch origin main && git checkout main && git merge --ff-only origin/main
```
اگر نشست روی شاخه‌ای مثلِ `claude/...` شروع شد، **آن مقصد نیست** — مقصد `main` است، چون
فقط `main` روی Render دیپلوی می‌شود.

> **مجوزِ پوش:** مالک اجازهٔ کامیت و پوشِ مستقیم روی `main` را هم در `CLAUDE.md` (دستورِ
> ایستادهٔ «Merge workflow») و هم **در خودِ پیامِ Routine** نوشته است، چون نگهبانِ خودکارِ
> مجوزها متنِ فایل‌های ریپو را «داده» می‌خواند نه «حرفِ مالک» (درسِ ALLIN1، ۲۰۲۶‑۱۰‑۰۷).
> force-push همیشه ممنوع است.

`scripts/supervisor/*.py` فقط کتابخانهٔ استاندارد لازم دارند؛ برای بندهای ۱ تا ۲ هیچ نصبی لازم نیست.

## ۱٫۲) کارِ جامانده از اجرای قبلی — **در هر دور، پیش از صف**

اگر اجرایی نتوانسته بود روی `main` پوش کند، `ship.sh` کارش را روی
`supervisor-pending/<برچسب>` گذاشته است (برچسب = شمارهٔ برگه، یا `run-<تاریخ>` برای دورِ کامل).
**فقط همین پیشوند** مالِ توست — به هیچ شاخهٔ دیگری (`claude/...` و بقیه) دست نزن:

```bash
git ls-remote --heads origin 'supervisor-pending/*'
```

برای هر کدام، یکی‌یکی:
1. `git fetch origin <شاخه> && git checkout -B pending FETCH_HEAD && git rebase origin/main`.
   تعارض ⇒ `git rebase --abort`، روی همان برگه `needs-owner` با نامِ شاخه و فهرستِ فایل‌های
   متعارض بنویس و برو سراغِ بعدی.
2. محیطِ بندِ ۳-۰ را بساز و `scripts/supervisor/ship.sh "<پیامِ کامیتِ اصلی>" <همان برچسب>` —
   خودش گیتِ قانونِ ۴ را می‌زند و روی `main` می‌فرستد.
3. موفق ⇒ اگر برچسب شمارهٔ برگه است، روی همان برگه جواب بده «کارِ اجرای قبلی حالا روی `main`
   است (کامیتِ …)» با همان نتیجه‌ای که خودِ کار داشت؛ اگر `run-<تاریخ>` است فقط در گزارش بنویس.
   بعد `git push origin --delete <شاخه>` (اگر رد شد مهم نیست؛ فقط بنویس).

## ۱٫۵) تیک‌خورده‌های مالک را بایگانی کن — **در هر دور، بدونِ استثنا**

```bash
python3 scripts/supervisor/inspection.py file
```
همین فرمان (v2) هر چیزی را هم که موقتاً در پایگاه‌داده مانده بود — درایو قطع بود یا md5 ِ آپلود
نخواند — به پوشهٔ درایوِ همان گزارش منتقل می‌کند (`to_drive` در خروجی). اگر `failed` خالی نبود یا
`left_in_db` با درایوِ وصل بیشتر از صفر ماند، در گزارش بنویس (متنِ خطا).

برگهٔ **آبی** = مالک تیک زده، یعنی «از نظرِ من تمام». تا بایگانی نشده، هایلایتش روی صفحهٔ مالک
می‌ماند و جای کارِ باز را اشغال می‌کند. خواستهٔ صریحِ مالک: «وقتی تایید مالک میشه روتین بعدی
دوره‌ای بایگانی کنه». **هر دور** یعنی این دورِ فوری هم؛ حتی وقتی صفِ فوری خالی است، و **قبل** از
خواندنِ صف. اگر چیزی نبود، ساکت رد شو. (اگر همین فرمان کدِ ۳ داد، بندِ ۲ را برای کدِ ۳ ببین.)

## ۲) صف را بخوان — کدِ خروج قرارداد است

```bash
python3 scripts/supervisor/inspection.py urgent
```

| کد | معنی | کار |
|----|------|-----|
| **۰** | صف خالی است | **همین‌جا تمام کن و هیچ چیز ننویس** (بندِ ۱٫۵ از قبل انجام شده). سکوت، خروجیِ درستِ یک دورِ خلوت است. |
| **۵** | یک برگه claim شد، در `docs/supervisor/inspection/URGENT.md` | برو بندِ ۳ |
| **۳** | صف **خوانده نشد** (سرور در حالِ بیدار شدن/دیپلوی، Render API در دسترس نیست، توکنِ ناظر غلط) | یک دقیقه صبر و یک‌بار دیگر؛ اگر باز ۳ داد، در یک جمله بگو صف خوانده نشد و **متنِ خطای چاپ‌شده** چه بود. **ساکت تمام نکن.** |

کدِ ۳ «چیزی نبود» **نیست**؛ خطاست. «نتوانستم نگاه کنم» و «نگاه کردم و چیزی نبود» اگر هر دو
سکوت تولید کنند، یک صفِ خوانده‌نشده می‌تواند روزها ساکت بماند. (سرورِ رایگانِ Render بعد از
بی‌کاری می‌خوابد و بیدار شدنش تا یک دقیقه طول می‌کشد — برای همین یک‌بار دوباره.)

## ۳) اگر برگه‌ای برداشته شد

0. **محیط** (هر اجرا روی کانتینرِ تازه است؛ «نصب نیست» را «محصول خراب است» گزارش نکن):
   ```bash
   python3 -c "import fastapi, pytest, pypdf, openpyxl, aiosqlite" 2>/dev/null || \
     { python3 -m pip install -q --ignore-installed cryptography && python3 -m pip install -q -r requirements.txt; }
   [ -d frontend/node_modules ] || (cd frontend && npm ci --no-audit --no-fund)
   python3 -c "import playwright" 2>/dev/null || python3 -m pip install -q playwright==1.56.0
   # هرگز `playwright install` نزن — کرومیومِ محیط در /opt/pw-browsers است
   ```
   (`--ignore-installed cryptography`: نسخهٔ debianِ cryptography را pip نمی‌تواند حذف کند و
   نصبِ requirements بدونِ آن نیمه‌کاره می‌ماند.)
1. `URGENT.md` را **کامل** بخوان؛ تصویرهای `shots/` را **باز کن و نگاه کن** (ابزارِ Read تصویر را
   نشان می‌دهد)؛ فایل‌های پیوستِ `files/` را **کامل** بخوان — نه خلاصه، هر قدر هم بلند باشند.
   سه‌تایی را با هم بخوان: متنِ برگه و یادداشت‌ها، *توضیحِ* هر فایل، و **متنِ کاملِ فایل**.
   1‑الف. **کادر را جدی بگیر.** «نشانیِ بازگشت»، «عنصر» (گره) و «جای دقیق داخلِ همان گره»
   (کسرها) را بخوان. وقتی خواسته «**در اینجا** …» است، «اینجا» را کادر گفته. قاعدهٔ کاملش بخشِ
   **۰-ب-۴** در `docs/supervisor/PROMPT.md` است و الزام‌آور است؛ برای چنین برگه‌ای `--place "…"`
   برای `fixed` اجباری است (ابزار بدونِ آن کدِ ۳ می‌دهد).
   1‑ب. **بندهای خواسته را بشمار** و در جواب یکی‌یکی ببند — «۱) … ۲) …»، بندِ انجام‌نشده هم با
   دلیل (بخشِ **۰-ب-۲**). بیشترین شکایتِ مالکانِ هر دو پروژهٔ الگو همین بوده: «خیلی چیزا رو توجه
   نکرده بود».
   1‑ج. یادداشتی که مالک **ذیلِ** برگه نوشته و کادرِ خودش را دارد، به **همان جای تازه** اشاره
   می‌کند، نه به کادرِ برگهٔ اصلی؛ فایل‌هایش هم مالِ همان یادداشت‌اند. «درخواستِ عمومی» کادر ندارد
   — خواسته‌ای کلی است؛ جای کار را خودت پیدا کن و بنویس کجاست.
2. `CLAUDE.md` و **همهٔ** `experiences/` را بخوان (الزام‌آور)، بعد طبقِ `docs/supervisor/PROMPT.md`
   (بخش‌های ۰-ب، ۰-ج، ۳، ۴، ۶) کار کن. پیش از کد، زنجیرهٔ وابستگی (۰-ج).
3. اگر خواسته دربارهٔ **ظاهر** است، صفحه را رندر کن و **ببین**:
   `python3 scripts/supervisor/screenshot.py "<نشانیِ بازگشت>" --selector "<گره>" --out /tmp/before.png`.
4. بفرست: `scripts/supervisor/ship.sh "type(scope): summary" <شمارهٔ برگه>` (pytest + بیلد ⇒ کامیت
   ⇒ `main` = دیپلوی). خروجِ **۷** یعنی `main` پوش را رد کرد و کار روی
   `supervisor-pending/<شمارهٔ برگه>` پارک شد: **متنِ دقیقِ خطا و نامِ شاخه** را روی برگه بنویس و
   `--outcome partial` بگذار (نه `needs-owner`) — کار تمام است و فقط مرج مانده، که دورِ بعد خودکار
   انجام می‌شود (بندِ ۱٫۲). خروجِ **۱** = گیت قرمز ⇒ پوش نشد؛ کد را درست کن.
5. برای `fixed`، از **همان‌جا** عکس بگیر و با خواسته تطبیق بده:
   `screenshot.py "<نشانیِ بازگشت>" --selector "<گره>" --out /tmp/after.png`. پیش‌فرضِ این ابزار
   **نسخهٔ محلیِ همان کامیت** است (پایگاه‌دادهٔ خالی، حسابِ یک‌بارمصرف) — توکنِ ناظر نمی‌تواند وارد
   SPA شود، پس عکس از production فقط با `--base <base>` و یک JWTِ کاربر در `LM_PAGE_MAP_TOKEN`
   ممکن است که معمولاً نداری. در جواب صریح بنویس «عکس از نسخهٔ محلی». بعد مطمئن شو دیپلو بالا
   آمده: `curl -s <base>/api/version` (آدرسِ `base` را `inspection.py whoami` چاپ می‌کند) باید همان
   کامیتِ تو را نشان بدهد — معمولاً ۳ تا ۱۰ دقیقه؛ اگر نیامد، همین را در جواب بنویس.
6. **نتیجه را درست انتخاب کن و جواب بنویس:**
   ```bash
   python3 scripts/supervisor/inspection.py answer <شماره> --text-file /tmp/answer.md \
       --outcome fixed|partial|needs-owner|not-done --after /tmp/after.png \
       --commit <sha> --dep 'نام=ok|missing|risk:توضیح' [--place "…"]
   ```
   `partial` و `not-done` یعنی برگه **بسته نشده** و دورِ بعد برمی‌گردد. بن‌بست ⇒ `needs-owner`
   با گزینه‌های مشخص. تا جواب ندهی، برگه از صفِ فوری بیرون نمی‌رود.
7. ثبت: یک سطر در `docs/supervisor/RUNLOG.md` («فوری #شماره: نتیجه، کامیت») و — اگر کد/داده عوض
   شد — یک مدخلِ `CHANGE` در انتهای `docs/overhaul/AUDIT_LOG.md` (قانونِ ۵)؛ درسِ قابلِ‌استفادهٔ
   مجدد ⇒ `experiences/` (ادغام، نه جایگزینی). امضا: `ناظرِ خودکار (Claude Code routine)` — بدونِ
   نامِ مدل. این ثبت‌ها را هم با `ship.sh` بفرست.

## ۴) بعد از جواب

دوباره `urgent` را بزن. اگر برگهٔ دیگری بود، **یکی‌یکی** به همان ترتیب. موازی نه — دو کار روی
یک برگه یعنی دو جوابِ متناقض زیرِ یک گفت‌وگو.

## ۵) بن‌بست و سقفِ زمان

به‌جای رهاکردن، `needs-owner` یا `not-done` با دلیلِ دقیق — برگهٔ بی‌جواب صف را بند می‌آورد.

**سقفِ زمان:** بیش از ~۴۰ دقیقه شد، همان برگهٔ جاری را با نتیجهٔ صادقانه (`partial` با آنچه
مانده) ببند و بقیه را به اجرای بعد بسپار. claim بعد از **۴۵ دقیقه** خودش آزاد می‌شود، پس هیچ
برگه‌ای گیر نمی‌کند — ولی برگه‌ای که claim شده و جواب نگرفته، تا ۴۵ دقیقه جلوی بقیه را می‌گیرد.

## ۶) گزارشِ پایانی

فقط اگر برگه‌ای جواب گرفت، کاری از `supervisor-pending/*` مرج شد، یا صف خوانده نشد: کوتاه و
فارسی — شمارهٔ برگه، نتیجه، کامیت، و هر چیزی که از مالک لازم است. این متن اعلانِ push می‌شود؛
**خودبسنده** باشد. صفِ خالی ⇒ **هیچ**.

## ۷) خطوطِ قرمز

- دادهٔ production را حذف یا بازنویسی نکن؛ برگه را **تأیید** یا **حذف** نکن (API هم اجازه نمی‌دهد).
- در گوگل درایو هیچ چیزی را حذف، جابه‌جا یا تغییرنام نده — پوشهٔ `LifeManagerData/inspection` مالِ برنامه است.
- قابلیتی را حذف نکن (قانونِ ۲) — قرنطینه + ثبت در `docs/overhaul/REMOVAL_CANDIDATES.md`.
- تستِ قرمز را «درست» نکن تا سبز شود؛ **کد** را درست کن.
- چیزی که نتوانستی بسنجی را «سنجیده‌شده» گزارش نکن.
- توکن، کلید یا رمز را هرگز چاپ، در فایل، در کامیت یا در گزارش نیاور.
- هیچ شناسه یا نامِ مدلی و هیچ نشانیِ نشستی در پیامِ کامیت یا هر چیزی که push می‌شود ننویس.
- ریپوهای دیگر (Detective-1، ALLIN1، …) را دست نزن.
- برای ادامهٔ چرخه هرگز `send_later` یا `create_trigger`/`update_trigger` صدا نزن — همین روتین
  خودش سه ساعتِ بعد برمی‌گردد.
