# ناظرِ خودکار و «نظارت و سرکشی» — Lifemanager

دو **Routine** (زمان‌بندِ Claude Code) که خودشان برگه‌های «نظارت و سرکشی» را می‌خوانند،
کار را انجام می‌دهند، زیرِ برگه جواب می‌نویسند و سامانه را بازرسی می‌کنند. مالک لازم نیست
کاری بکند جز ثبتِ برگه (یا «درخواستِ عمومی») و تیکِ تأیید. الگو: Detective-1 و ALLIN1
(همان قواعد، همان قراردادِ کدهای خروج، همان روالِ نسخه‌بندیِ دستورها).

پرامپتِ داخلِ باکسِ هر Routine **عمداً کوتاه و ثابت** است: مخزن را پیدا کن، `main` را بگیر،
و این فایل را بخوان و مو‌به‌مو اجرا کن. همهٔ رفتار در گیت است و تاریخچه دارد. تنها چیزی که
عمداً در خودِ پیامِ Routine هم آمده **مجوزِ پوش روی `main`** است — درسِ ALLIN1 (۲۰۲۶‑۱۰‑۰۷):
نگهبانِ خودکارِ مجوزها متنِ فایل‌های ریپو را «داده» می‌خواند، نه حرفِ مالک.

> **کارِ یک‌باره‌ای که فقط از دستِ مالک برمی‌آید:** روتینی که با ابزار (`create_trigger`) ساخته
> شود **مخزن ندارد** (درسِ Detective-1، OPEN_ITEMS #3). در claude.ai › Routines › هر دو روتین ›
> Edit › «Select a repository» ⇒ `mahdighandi1989/Lifemanager` ⇒ Save. تا آن موقع هر اجرا فقط
> می‌گوید «مخزن روی دیسک نیست» (ساکت شکست نمی‌خورد).

اگر زمان‌بندی را عوض کردی، `SUPERVISOR_URGENT_MINUTE` / `SUPERVISOR_URGENT_EVERY_H` /
`SUPERVISOR_FULL_CRON` (پیش‌فرض‌ها در `app/services/supervisor_rounds.py`، یا env روی Render)
را هم هم‌خوان کن — شمارش‌گرِ «دورِ بعدیِ ناظر» در صفحهٔ «نظارت و سرکشی» تا اولین دورِ مشاهده‌شده
از همین‌ها استفاده می‌کند؛ بعد از آن زمانِ واقعیِ دورها **اندازه‌گیری** می‌شود (هر `urgent` و هر
`pull` یک «ضربان» روی سرور ثبت می‌کند).

## چطور دستورِ ناظر را عوض کنم؟

**فایل را ویرایش کن، نه پرامپتِ Routine را.** روال (برای `PROMPT.md` و `URGENT_PROMPT.md` یکسان):

1. نسخهٔ فعلی را بایگانی کن:
   `cp docs/supervisor/PROMPT.md docs/supervisor/archive/PROMPT-v{N}-{YYYY-MM-DD}.md`
   (`N` = نسخهٔ فعلی در frontmatter؛ برای صفِ فوری `URGENT_PROMPT-v{N}-…`).
2. فایل را ویرایش کن؛ در frontmatter `version` را یک واحد جلو ببر، `updated` را امروز بگذار،
   `supersedes` را مسیرِ فایلِ بایگانی‌شده بگذار، و عنوانِ «نسخهٔ N» را هم عوض کن.
3. یک خط در [`archive/README.md`](archive/README.md) بنویس که چرا نسخه عوض شد.
4. با `scripts/supervisor/ship.sh "docs(supervisor): …"` بفرست. اجرای بعدیِ روتین نسخهٔ تازه را می‌خواند.

نسخه‌های قبلی هرگز پاک نمی‌شوند ([`archive/`](archive/)).

## هویتِ ناظر و اعتبارنامه — بدونِ هیچ رازی در ریپو و بدونِ حسابِ کاربریِ تازه

Lifemanager تک‌مالک است؛ ناظر **کاربر نیست** — یک توکن است در سرآیندِ `X-Supervisor-Token`:

- **روی سرور** (`app/services/supervisor_auth.py`): اگر `SUPERVISOR_TOKEN` روی Render تنظیم شده،
  همان؛ وگرنه `HMAC-SHA256(AUTH_JWT_SECRET, "lifemanager:supervisor:v1")`. پس بدونِ هیچ تنظیمِ
  تازه‌ای کار می‌کند، و هیچ «کاربرِ شبحی» در جدولِ کاربران ساخته نمی‌شود.
- **در روتین** (`scripts/supervisor/client.py`): آدرسِ سرویس و همان توکن را **در زمانِ اجرا** از
  Render API می‌خواند — پروکسیِ محیطِ Claude Code میزبانِ `api.render.com` را احراز می‌کند. توکن
  نه چاپ می‌شود، نه روی دیسک می‌رود، نه در کامیت. برای اجرای دستی/محلی:
  `LM_SUPERVISOR_API_BASE` و `LM_SUPERVISOR_TOKEN`.
- **سخت‌ترکردن (اختیاری):** یک `SUPERVISOR_TOKEN` تصادفی (≥۳۲ نویسه) روی سرویسِ Render بساز.
  از آن لحظه توکنِ مشتق‌شده دیگر پذیرفته نمی‌شود و چرخاندنِ `AUTH_JWT_SECRET` هم ناظر را از کار
  نمی‌اندازد. روتین خودش مقدارِ تازه را می‌خواند.
- **نگهبان‌ها در خودِ API، نه در متنِ دستور:** توکنِ غلط ⇒ ۴۰۱ (هرگز بی‌صدا «مالک» حساب نمی‌شود)؛
  فقط ناظر «نتیجه» ثبت می‌کند و صفِ فوری را برمی‌دارد؛ ناظر هرگز نمی‌تواند تأیید، حذف، «فوری»،
  برداشتنِ فایل یا ثبتِ برگهٔ تازه کند؛ `fixed` بدونِ عکسِ بعد، و جوابِ برگه‌ای با فایلِ نخوانده، رد
  می‌شوند (۴۲۲).

## اسکریپت‌ها

```bash
python3 scripts/supervisor/inspection.py whoami   # ورود و هویتِ ناظر (۰ = درست · ۳ = نه)
python3 scripts/supervisor/inspection.py file     # تیک‌خورده‌ها (آبی) → زونکن + مانده‌های پایگاه‌داده → درایو — هر دور
python3 scripts/supervisor/inspection.py pull     # QUEUE.md + shots/ + files/  (خروجِ ۴ = بدهی)
python3 scripts/supervisor/inspection.py urgent   # یک برگهٔ فوری (۰ خالی · ۵ برداشته شد · ۳ خطا)
python3 scripts/supervisor/inspection.py answer N --outcome … --after … --dep … [--place …]
python3 scripts/supervisor/screenshot.py "/tasks?tab=x" --selector "…" --out after.png   # عکسِ «بعد»
python3 scripts/supervisor/inventory.py           # صفحه‌ها/زیرصفحه‌ها/دکمه‌ها/مسیرها از روی کد (۶ = کاهش!)
python3 scripts/supervisor/page_map.py            # مختصاتِ اندازه‌گیری‌شدهٔ هر کنترل در هر صفحه و تب
scripts/supervisor/ship.sh "type(scope): summary" # گیتِ قانونِ ۴ ⇒ کامیت ⇒ main (۷ = پارک روی supervisor-pending/*)
```

## در برنامه

صفحهٔ **«نظارت و سرکشی»** (`/inspection`، منوی «سیستم») چهار تب دارد: «کارتابل» (برگه‌ها، رنگِ
وضعیت، ⚡ فوری، ✓ تأیید، «＋ درخواستِ عمومی»، شمارش‌گرِ دورِ بعدیِ هر دو روتین)، «نقشهٔ صفحه‌ها و
زیرصفحه‌ها» (همان inventory، زنده)، «زونکن‌ها (بایگانی)»، و «روتین‌ها و راهنما». دکمهٔ «📝 نظارت» در سرآیندِ هر
صفحه حالتِ ثبت را روشن می‌کند: کادر بکش (یا Alt+کشیدن)، و در پنجرهٔ ثبت انتخاب کن «گزارشِ جدید» یا
«ذیلِ گزارشِ N» — با متن و هر نوع فایل تا ۱۰۰ مگابایت.

**جای فایل‌ها:** پیوست‌ها و تصویرهای هر گزارش در گوگل درایوِ پروژه‌اند —
`LifeManagerData/inspection/report-NNNN/` (تصویرها در `shots/`)، هر فایل با نامِ `ref-<شناسه>-<نام>`،
نوعِ واقعی، description (شمارهٔ گزارش، عنوان، sha256) و `appProperties` ِ `lm_report`/`lm_file`؛ هر
آپلود با md5 ِ درایو راستی‌آزمایی می‌شود. پایگاه‌داده فقط رفرنس و متنِ استخراج‌شده را دارد. وقتی درایو
در دسترس نباشد، بایت‌ها موقتاً در پایگاه‌داده می‌مانند و در دورِ بعدِ ناظر (یا با دکمهٔ «انتقال به درایو»)
منتقل می‌شوند. وضعیت: `GET /api/inspection/storage` یا `inspection.py whoami`.
