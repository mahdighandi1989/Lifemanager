Failure signatures:

- (b) The system accepts or parses only x, y: partly true. The guess-kit formula parser (a17 parseFormula) accepts only the Latin variable n or x, so his «ح» notation cannot be used there → S3 below.
- (c) Persian symbols (ن، ح) break in equations: not seen. «ح۲: حجم آب‌نمک ۲۵٪…» and «÷» render correctly (screenshot s6).

## Defects
- [S3] (b) The guess kit's «فرمول بر حسبِ n» accepts only n or x (src/app/a17_kpractice.js parseFormula: `/^[0-9n x.+\-*/^()]+$/`). A student who chose «ح» cannot get a code check of his formula unless he switches back to Latin letters. That is the exact aversion this scenario is about.
- [S3] (b) There is no notation support. «شکل، جدول یا نام‌گذاری» is a single-line free-text input: no words/symbols two-column structure, and no check that one symbol names two objects. The guidance came only from the model.
- [S3] (b) There is no fitting home for a homework problem with a definite answer that the student does not yet know. The 🔭 live hook frames it as «پاسخِ این مسئله را هیچ‌کس نمی‌داند — … دربارهٔ درستیِ گام‌ها داوری نکن» (p7), which is false for a school exercise. The solved-problem simulator needs the final answer up front.
