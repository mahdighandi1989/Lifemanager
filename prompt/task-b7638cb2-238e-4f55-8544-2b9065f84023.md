# Align User and OAuthUser in Auth Pipeline

## Raw Idea

## 📋 شرح ناسازگاری
در pipeline `auth` یک ناسازگاری منطقی پیدا شد:

`app/dependencies/auth.py` lists `app.models.user.User` as an interaction, while `app/models/user_oauth.py` defines `OAuthUser` and is described as defining 'the SQLAlchemy ORM model for an OAuthUser entity'. It's unclear if `app.models.user.User` refers to the `OAuthUser` defined in `user_oauth.py` or if there's a separate, undefined `User` model. This inconsistency in naming and lack of clarity about which model is the primary user entity can lead to confusion, potential errors in data access,

## 💥 پیامد (impact)
If different user models are implicitly used or if the naming is inconsistent, it could lead to: Incorrect data retrieval or storage; Bugs in authentication or authorization logic if the wrong model's attributes (e.g., roles, permissions) are accessed; Maintenance overhead due to confusion; Security

## 🛠 پیشنهاد رفع اولیه
Clarify the relationship between `User` and `OAuthUser`. If `OAuthUser` is the primary user model, update all references (e.g., in `app/dependencies/auth.py`) to explicitly use `app.models.user_oauth.OAuthUser`. If there are two distinct user models, define `app.models.user.User` and clearly document their respective roles and how they interact within the authentication pipeline.

coherence issue یعنی دو بخش کد فرض‌های ناسازگار دارند — معمولاً نشانه‌ی refactor ناتمام یا feature flag rot است. این کلاس bug ها در test معمولی پیدا نمی‌شوند چون unit test ها در silo اجرا می‌شوند.
