بر اساس درخواست کاربر، مدل‌ها باید 'داینامیک' عمل کنند و 'هاردکد نباشن'. آن‌ها باید بتوانند 'درخواست کامل ببینن' و 'هیچ محدودیتی توکنی براشون نباشه' و 'هزینه هم مسئله‌ای نباشه'. این نشان می‌دهد که سیستم باید قابلیت ذخیره و بازیابی پرامپت‌های طولانی و پیچیده را داشته باشد و مدل‌های AI باید بتوانند context بزرگی را مدیریت کنند.

در کدبیس موجود، `app/routes/ai.py` شامل endpointهایی برای مدیریت پیکربندی‌های مدل AI (`/ai/configs`) است که شامل `GET`, `POST`, `PATCH`, `DELETE` می‌شود. این نشان می‌دهد که زیرساخت بک‌اند برای مدیریت مدل‌ها وجود دارد. فایل `docs/API.md` نیز این endpointها را تأیید می‌کند. برای پشتیبانی از 'باکس' پرامپت، نیاز است که schema و مدل `AIModelConfig` در بک‌اند (احتمالاً در `app/schemas/ai_schema.py` و `app/models/ai_model_config.py`) یک فیلد جدید برای ذخیره 'default_prompt_template' یا مشابه آن داشته باشند. در فرانت‌اند، نیاز به ایجاد یک صفحه جدید (مثلاً `frontend/src/pages/AISettingsPage.jsx`) و اضافه کردن لینک به آن در `frontend/src/components/Sidebar.jsx` است تا کاربر بتواند به 'صفحه تنظیمات' دسترسی پیدا کند. این صفحه باید با `frontend/src/lib/api.js` برای تعامل با endpointهای AI بک‌اند ارتباط برقرار کند.

import openai # or similar AI client
from app.core.config import settings
from typing import Optional

async def generate_text_response(
    db,
    prompt: str,
    user_id: int,
    system_role_prompt: Optional[str] = None,
    task_context: Optional[str] = None
):
    messages = []
    if system_role_prompt:
        messages.append({"role": "system", "content": system_role_prompt})
    
    user_content = ""
    if task_context:
        user_content += f"Context: {task_context}\n\n"
    user_content += f"Task: {prompt}"
    
    messages.append({"role": "user", "content": user_content})

    # Ensure no artificial token limits are imposed by the application
    # Rely on the model's default max context or set a high value if needed

        api_key=settings.OPENAI_API_KEY,
        # max_tokens=4096 # Example: set a high token limit if not default
    )

کاربر درخواست کرده است که مدل‌های هوش مصنوعی «درخواست کامل ببینن و هیچ محدودیتی توکنی براشون نباشه و هزینه هم مسئله‌ای نباشه». این به این معنی است که سیستم باید مکانیزمی پیاده‌سازی کند تا اطمینان حاصل شود که مدل هوش مصنوعی کل درخواست کاربر و تمام زمینه مرتبط را بدون هیچگونه برش یا خلاصه‌سازی به دلیل محدودیت‌های توکن دریافت می‌کند. این مرحله همچنین به معنای انتخاب یا پیکربندی سرویس‌های هوش مصنوعی است که می‌توانند زمینه‌های بزرگ را مدیریت کنند و در آن هزینه استفاده از توکن بالاتر برای این ویژگی خاص عامل بازدارنده‌ای نیست. کاربر همچنین تأکید دارد که AI «باید بدونن نسبت به اون وظایفی که هست و اضافه می‌شه، باید حسب کارهایی که مثلاً انجام دادم چه عکس‌العملی داشته باشن و حسب اون چیزهایی که من باید انجام بدن چه من باید انجام بدم چه واکنشی باید در پیام‌هایی که برام می‌فرستن و فیدبکی که می‌دن حالا چه توی اعلانات یا توی اونجایی که مثلاً ثبت می‌شه بهم بگن.» این نشان می‌دهد که AI باید قادر به درک عمیق‌تر از وضعیت فعلی و گذشته کاربر (وظایف، پروژه‌ها، فعالیت‌ها) باشد و بازخوردهای هوشمندانه‌تر و مرتبط‌تری را از طریق اعلانات یا سایر مکانیزم‌های ثبت‌شده ارائه دهد. این قابلیت برای 'مدیریت هوشمند زندگی، وظایف و پروژه‌ها' که در README.md ذکر شده، حیاتی است. فایل‌های کلیدی مرتبط شامل `app/routes/ai.py` برای مدیریت درخواست‌های API هوش مصنوعی، `app/services/ai_service.py` و `app/services/ai/nlp_service.py` برای منطق اصلی تعامل با مدل‌های AI و `app/services/notification_service.py` برای ارسال بازخوردها هستند.

## 🔍 Context و وضعیت فعلی
کاربر درخواست پیاده‌سازی سیستمی برای «واکنش زمینه‌ای به اقدامات کاربر» را دارد. این سیستم باید اطلاعات مربوط به «اقدامات کاربر، وظایف تکمیل شده و جریان‌های کاری در حال انجام» را به «زمینه مدل هوش مصنوعی» تغذیه کند. هدف این است که مدل هوش مصنوعی بتواند «پاسخ‌ها یا رفتار خود را به صورت دینامیک بر اساس این فعالیت کاربر در زمان واقعی تنظیم کند» و «درک خود را از پیشرفت و تاریخچه کاربر نشان دهد». کاربر به طور خاص اشاره می‌کند که مدل باید «نسبت به اون وظایفی که هست و اضافه می‌شه، باید حسب کارهایی که مثلاً انجام دادم چه عکس‌العملی داشته باشن» و این واکنش باید «در پیام‌هایی که برام می‌فرستن و فیدبکی که می‌دن حالا چه توی اعلانات یا توی اونجایی که مثلاً ثبت می‌شه بهم بگن». این درخواست شامل کلیدواژه‌هایی مانند «وظایفی که هست و اضافه می‌شه»، «کارهایی که مثلاً انجام دادم»، «عکس‌العملی داشته باشن»، «اعلانات» و «اونجایی که مثلاً ثبت می‌شه» است. 

برای پیاده‌سازی این قابلیت، نیاز است که فعالیت‌های کاربر در سیستم (مانند ایجاد، به‌روزرسانی یا تکمیل وظایف و پروژه‌ها) رصد شده و این داده‌ها به عنوان یک 'context' به درخواست‌های ارسالی به مدل هوش مصنوعی اضافه شوند. مدل هوش مصنوعی (که از طریق `app/routes/ai.py` و `app/services/ai_service.py` با آن تعامل می‌شود) باید قادر باشد این زمینه را درک کرده و پاسخ‌های شخصی‌سازی‌شده ارائه دهد. همچنین، اگر فیدبک‌ها قرار است در قالب اعلانات باشند، `app/routes/notifications.py` و `app/services/notification_service.py` نیز درگیر خواهند شد. ساختار مدل‌های `app/models/task.py`، `app/models/project.py` و `app/models/todo_item.py` برای جمع‌آوری داده‌های فعالیت کاربر حیاتی است.

این درخواست به کلیدواژه‌هایی مانند «چیزهایی که من باید انجام بدن»، «واکنشی باید در پیام‌هایی که برام می‌فرستن»، «فیدبکی که می‌دن»، «اعلانات» و «ثبت می‌شه» اشاره دارد. همچنین، بر «داینامیک و هوشمند» بودن عملکرد AI و محدودیت آن در «چارچوب اون پرامپتی که در اون باکس چیز براشون قرار می‌دم» تأکید شده است.

async def perform_dynamic_analysis(db: AsyncSession, user_id: int, user_prompt: str, context_ids: dict) -> DynamicAnalysisResponse:
    # 1. Fetch relevant context data (e.g., tasks, projects)
    context_data = {}
    if 'task_id' in context_ids:
        task = await get_task_by_id(db, context_ids['task_id'], user_id)
        if task: context_data['task'] = task.description
    # ... fetch other contexts ...

    # 2. Construct a sophisticated prompt for the LLM

    Context: {context_data}
    
    Provide dynamic and intelligent insights, make decisions, and suggest actionable steps. Your response should go beyond simple rule-based logic.
    Format your response as a JSON object with 'insights', 'decisions' (list of strings), and 'suggested_actions' (list of strings).
    """

    # 3. Call the AI provider
    ai_response_raw = await provider_service.query_model(full_prompt)

## ⚠️ ریسک‌ها و موارد احتیاط
1.  **افزایش زمان پاسخ AI**: افزودن مرحله اعتبارسنجی پس از دریافت پاسخ از مدل AI می‌تواند latency را افزایش دهد، به خصوص اگر منطق اعتبارسنجی پیچیده باشد. این امر می‌تواند بر تجربه کاربری در endpointهایی مانند `POST /ai/generate` و `POST /ai/query` تأثیر بگذارد.
2.  **پیچیدگی منطق اعتبارسنجی**: پیاده‌سازی یک `_enforce_prompt_constraints` هوشمند و دقیق که بتواند "خارج شدن از مسیر" را به درستی تشخیص دهد، دشوار است و ممکن است نیاز به استفاده از مدل‌های NLP داخلی یا تکنیک‌های پیشرفته داشته باشد که در حال حاضر در `app/services/ai_service.py` موجود نیست.
3.  **تأثیر بر `app/services/ai/nlp_service.py`**: اگر `app/services/ai_service.py` به `app/services/ai/nlp_service.py` برای پردازش‌های عمیق‌تر AI وابسته باشد، تغییرات در `ai_service.py` ممکن است نیاز به هماهنگی یا تغییراتی در `nlp_service.py` داشته باشد که در حال حاضر deep-read نشده است.
4.  **امنیت**: اگر `constraints` به صورت مستقیم به مدل AI ارسال شود (به جای اینکه در بک‌اند اعمال شود)، ممکن است منجر به حملات prompt injection شود. باید اطمینان حاصل شود که اعمال محدودیت‌ها در لایه بک‌اند و به صورت امن انجام می‌شود.
5.  **تجربه کاربری**: اگر محدودیت‌ها به صورت سختگیرانه اعمال شوند و منجر به رد شدن مکرر پاسخ‌های AI یا تعدیل‌های غیرمنتظره شوند، ممکن است تجربه کاربری را کاهش دهد.
